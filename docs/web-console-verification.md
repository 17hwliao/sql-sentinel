# 双控制台迁移修复与本机验证（2026-10-22）

交付为两个独立 Web 服务：共享一个 Clerk 身份应用，分别映射网关租户与 SQL 项目权限。当前完成源码实现及受控、本机 Linux 容器验证；真实 Clerk、邮件验证、跨子域 SSO 和云域名尚未配置或验收。机器可读结果见同目录 `web-console-verification.json`。

## Review 发现的处理

| 问题 | 当前实现与证据 |
|---|---|
| 登录 hash 导致表单销毁 | 认证 hash 保留稳定容器，业务导航才卸载；测试覆盖验证页跳转与重复点击 |
| 身份切换旧响应覆盖 | 请求绑定身份代次和会话，覆盖 getToken、成功响应、延迟错误正文；产品授权撤销清空旧状态 |
| 已登录未授权无法退出 | 独立展示产品授权缺口，保留退出/切换与重新检查入口 |
| RAG 上传内容类型错误 | 使用 text/plain 或 text/markdown，支持明确版本；测试调用实际提交处理器 |
| 性能证据字段不匹配 | 使用实际 Go JSON 字段；Go 和前端共享性能 fixture，覆盖合格/不合格、耗时及噪声 |
| 最近任务 30 并发产生 429 | 改为后端持久项目列表，一次有界分页请求；按项目及允许表过滤，支持跨浏览器 |
| 接入配置写死模型、缺预检 | 当前目录选择模型，核对工具能力、有效 CNY 价格、余额冻结上限和 readyz，再生成 OpenCode/Claude 配置 |
| 诊断摘要遗漏事实 | 显示 statement、facts 和 required_verification；原 JSON 保留 |
| 检索不显示片段 | 使用 items[].text 及绑定 citation；回答与仅检索分别适配 |

另在浏览器验证中修复文档列表误读任务页控件的问题，并补严格缺失控件的 DOM 回归。Key 管理权限只接受布尔 true，不能以字符串等 truthy 值获得权限。

## 补齐的界面和服务端能力

- AgentMesh：模型价格、图片资产列表/私有回读/删除、调用 trace、业务就绪/提供商状态/计量发件箱摘要、受限平台管理。管理员可查询/创建/启停租户与更新路由、管理充值/预算 grant/异常对账；管理员操作记录身份、动作和状态，不记录凭据或请求内容。
- SQL Sentinel：数据库持久任务分页与状态筛选、手动 candidate_spec、当前知识文档列表/版本/删除、审计分页、历史搜索、集成配置状态、当前项目令牌元数据与撤销。新增查询不返回原始 SQL、原始令牌或其他项目内容。
- 普通成员、Key 管理员、平台管理员、SQL 各角色分别判断；前端隐藏按钮不能代替服务端校验。平台注册后的产品开通仍是私有成员文件配置，不自动赠送余额。
- 配置生成器核对生产域名、共享身份实例及文件权限，拒绝覆盖已有私有目录；预检脚本检查私有映射/可读凭据与业务 readyz。哈希静态资源可长期缓存，HTML/API 不缓存。
- 上线设计见 AgentMesh 仓库 `deployments/backend-stack/WEB-PRODUCTION.md`，采用三个 HTTPS 子域、两套只读非 root 控制台、原有私网业务及数据服务；补齐 Compose/Caddy 配置和 CI 检查。

完整 Go 套件中 AgentMesh 有两个默认跳过入口：显式资源测试另行运行并通过；崩溃探针的子进程入口由父测试在受控条件调用，不独立强制运行。没有把跳过计作通过。

安全扫描发现 Go 1.26.9 受 [GO-2026-6809](https://pkg.go.dev/vuln/GO-2026-6809) 影响，两个应用、fixture 及代理构建统一升级至 1.26.10，之后重新测试和扫描。代理模块级枚举仍报告 [GO-2026-5932](https://pkg.go.dev/vuln/GO-2026-5932)，涉及未维护的 x/crypto/openpgp；当前代理没有导入该包，符号与导入包扫描均为 0，官方没有该包的修复版本。未屏蔽此告警，也不宣称所有基础镜像 OS 包均完成 CVE 审计。

## 必须保留的使用边界

1. 真正 Clerk 邮件/共享会话、真实用户通过浏览器调用 Go/模型的全链路、云端 TLS 与目标网络未验收。未配置身份时 `/readyz` 和业务登录返回 503 是正确拒绝；`/healthz` 200 仅代表进程存活。
2. 网页可预检当前控制台专用 Key 的工作空间条件；新应用 Key 仍须单独核验。当前轮未重跑真实 OpenCode/Claude 模型调用，不能把下载配置等同于所有工具、MCP 或长任务兼容。
3. 充值为受控管理员账本入账，调用按 token 从余额扣除；没有在线支付收单、退款或商户对账集成。
4. 知识文档为当前版本替换，不提供历史版本回滚。ES/GitHub 等可选集成只有配置与相应服务可用后才工作，状态页不把配置存在等同于联调成功。
5. 本方案为单机部署，不承诺高可用、云端容量或生产负载下的 L3 收益。备份、密钥保护与恢复遵循上线手册。

验证命令入口：进入各仓库 `web/` 目录运行 `npm test`、`npm run build`；`scripts/verify-integrations.py` 运行隔离 Linux/MySQL/Redis/Kafka 测试；`scripts/validate-contracts.py` 验证 OpenAPI；部署目录两个 setup 测试验证配置。实际资源/容器及浏览器记录保留在本地验收工件，不上传私有环境、测试数据库或凭据。
