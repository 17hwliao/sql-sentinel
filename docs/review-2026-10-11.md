# 后端改进审查（2026-10-11）

本轮覆盖待提交的 AST 准入/表权限、改写与结果指纹、工作流状态副本、RAG 对照和部署入口；此前后端扩展的功能边界见 backend-roadmap.md。本次由当前开发 Agent 审查，不是额外独立审计。

## 已修复的确认问题

- P1：非递归 CTE 名称在定义前即被登记。同名真实表或后定义 CTE 的引用可能从物理表清单中消失，绕过服务表权限。现仅在 CTE 定义遍历完成后登记名称，保留可见的外层与前序 CTE。修复前 AST/服务权限回归失败，修复后通过；真实 MySQL 对照确认同名、前向引用与外层遮蔽行为。
- P2：RAG 对照接受空白“无关上下文”，渲染时又丢弃它，使该条件退化为无上下文。现拒绝空白对照文本；负例在修复前失败、修复后通过。
- P2：补充私有环境/秘密/备份的 Git 与 Docker 构建上下文排除，并从 README 链接可克隆的联合部署模板。

## 验证及边界

最终 Windows 全量测试与 Linux race 各为 237 PASS、0 FAIL、3 SKIP；vet、Linux 全项目编译、govulncheck 均通过。独立临时 MySQL 补测为 17 PASS：工作流不变量一项、结果对照父测试一项及 15 个 SQL 子例。默认跳过的两项 MySQL 测试已由该补测覆盖，外部实验锁集成未在这次审查重跑。

默认测试的 SKIP 不计为通过。结果指纹仅证明有界样本的一致性；真实模型 RAG 质量、生产 DDL、云端容量、代表性 L3 与 Kubernetes 集群没有由这些测试验证。源码提交不会更新现有运行容器或历史发行包。

优先可选方向：扩充真实 MySQL 名称解析反例集，覆盖更多嵌套 CTE/派生表组合，再考虑扩大 SQL 支持范围。依据是此次权限遗漏已由真实数据库证明；新增小规模反例的成本较低。此建议不自动开启下一项开发。
