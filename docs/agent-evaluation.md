# Agent v1 场景与固定流程对照

日期：2026-11-06。本页记录本轮新增闭环的本地确定性场景测试，不是数据库性能评测或真实模型评测。固定流程 `DraftBounded` 仍保留为默认兼容路径。

## 可复现命令

```sh
go test ./internal/agentgraph -run TestLoopScenario -count=1 -v
```

测试代码：`internal/agentgraph/loop_scenarios_test.go`。模型是同一确定性场景策略的 fixture；工具是返回明确观察的 fixture。两种流程采用同一 SQL、Schema、候选和工具判定规则，并使用共同的最多 3 次模型调用上限。固定流程输出 CandidateSpec，Agent 流程按新协议输出动作；不声称两者使用了同一真实模型或完全相同的提示词。

## 对照结果

| 场景 | 原固定流程 | Agent 模式 | 代价与含义 |
| --- | --- | --- | --- |
| 首个候选验证通过 | 1 次模型、1 次工具验证，得到已验证候选 | 2 次模型、1 次工具验证，模型依据观察明确结束并选定候选 | Agent 多一次结束决策；没有证据说明它在此例更快或更省钱 |
| 首个候选被工具拒绝 | 1 次模型、1 次工具验证，固定流程无法把验证观察交回模型 | 3 次模型、2 次工具验证：先拒绝、根据观察改选第二候选、明确结束 | 证明新增的反馈通路；拒绝原因和第二候选成功均为受控 fixture，不能推导生产优化收益 |

每次运行通过测试日志输出真实发生的 fixture 调用次数、结果及编排 wall-clock 毫秒数。耗时没有稳定基准或足够重复样本，可能低于时钟分辨率，因此不用于比较性能。此次测试没有调用付费模型，不产生新增模型费用；不以此声称真实模型零费用。

## 额外反例

独立场景覆盖：合法无候选结果；跨任务／伪造证据、未验证选择；换索引名重复提交同一规范化候选；跨表动作、未知字段和重复 JSON key；畸形模型输出计入调用限额；同一预算存储被另一执行尝试复用时不重置；模型错误、基础设施错误、租约丢失和鉴权错误不写成无收益；取消与截止时间；未配置历史检索不能调用、可选历史检索暂不可用不阻断独立诊断、检索鉴权失败必须停止；快照、Schema、版本或候选 hash 不匹配时不能沿用观察。

这些场景证明公开引擎契约及编排分支。它们不能替代 MySQL 的持久计数／事务、命名锁、DDL 清理、快照变化和旧租约覆盖测试，也不能替代 MCP 协议、真实编程客户端、真实模型及云端使用验收。对应证据应由各自的实际联调记录给出，不能从本页推定已通过。
