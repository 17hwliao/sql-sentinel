# 极快查询的批量轮次测量

## 原始需求

阶段 00 的 candidate 查询中位数约 2.9ms、绝对 scaled MAD 约 0.38ms，
但相对噪声比为 13.02%，无法通过 10% 准入线。不能为使结果好看而修改准入线；
需要在同一 SQL、同一环境和同一判定规则下，增加“每轮连续执行多次并折算单次耗时”的测量协议，
用更长的测量窗口降低调度抖动对极快查询的影响。

## 目标

- `bench` 支持 `--executions-per-round`（正整数，默认 `1`）；每次预热、标定和正式 A/B 轮次均执行相同次数。
- 一轮的计时覆盖 N 次完整 `QueryContext → rows.Next/Scan → rows.Err/Close`；报告的 `raw_ms`、中位数和 MAD 是 `batch_elapsed / N` 的单次折算值。
- 报告记录 `executions_per_round`，使任何消费者能知道数值不是单条 SQL 的直接墙钟耗时。
- `N=1` 保持当前协议与输出语义；`N>1` 不改变查询参数、索引、快照门禁、版本门禁、方向判定、10% 准入线或 L1/L2 判定规则。
- 在 100 万行的现有双容器数据上重新运行两次 20 轮标定和一次正式测量；只有新报告 `eligible_for_performance_claim=true` 才可声称收益。

## 非目标

- 不调低 10% 噪声准入线、不添加绝对噪声门槛、不回填历史 JSON。
- 不实现写压、SQL 改写、Agent/Eino、Webhook、Redis 或前端。
- 不修改两侧数据生成、索引定义、MySQL 参数或 Docker 镜像。

## 默认假设

- 默认 `N=1`，兼容现有调用；真实重测默认使用 `N=10`，而不是把 N 写死在代码中。
- 单轮内的 N 次执行复用一个已准备好的语句，但每次都完整读取并关闭结果集；不缓存查询结果。
- 容器外的 `astrbot`、`napcat`、`mysql` 仅在真实重测前临时停止，实验结束后原样启动；不删除容器或 volume。
- 若 `N=10` 仍不通过准入，报告保留 L1，下一阶段重新评估协议，不再继续叠加临时调参。

## 验收条件

1. `--executions-per-round=0` 或负数必须明确报错；未传参等价于 `1`。
2. 每个轮次执行恰好 N 次完整查询；任一次失败或上下文取消即返回错误，后续调用不再继续。
3. 报告 JSON 能读到 `measurement_protocol.executions_per_round`；标定和正式测量均使用该值。
4. `N=1` 的纯逻辑测试证明单次样本值不被额外除法或批量路径改变。
5. 新的真实实验继续通过版本、快照、candidate 索引门禁；证据等级完全由既有 admission 规则计算。
