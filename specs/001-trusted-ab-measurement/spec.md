# 可信测量 Spike：双影子实例 A/B 判定

**原始需求**：实现第一个可运行垂直切片，只做「可信测量 Spike」——双实例、同快照、A/B 交替测量、噪声门槛判定、候选索引展示读收益。

## 目标

让使用者用一条命令，对同一条只读查询在两套完全相同的隔离数据库实例上交替测量，得到一份可复现的判定：本次差异是真实收益，还是落在环境噪声内。

## 非目标

- 不做 LLM、Agent 编排、PR Webhook、前端、历史检索、任务队列
- 不做写放大测试、并发写代价测量
- 不做自动建索引决策；候选索引由使用者显式指定
- 不接触任何生产环境或真实业务数据
- 不做 SQL 改写与等价性校验（属后续切片）
- 不使用 WSL；不改动系统网络与容器平台全局设置

## 验收条件

1. **给定** 全新环境且容器已启动，**当** 执行造数命令，**则** 两个实例各自载入相同规模的基准数据
2. **给定** 两实例已载入数据，**当** 执行快照校验，**则** 输出两侧 SHA-256 摘要并明确判定一致或不一致
3. **给定** 两实例快照一致，**当** 执行一次 A/B 测量，**则** 报告含双侧中位延迟、噪声比（离散度须按 1.4826 缩放）与 Better / Worse / NotSignificant 三态判定之一
4. **给定** 中位数差异未超过噪声门槛，**当** 生成判定，**则** 结论必须是 NotSignificant，不得声称收益
5. **给定** 在候选侧建立一个候选索引并重测，**当** 生成报告，**则** 能体现读取侧的差异方向
6. **给定** 快照校验不一致，**当** 请求测量，**则** 拒绝出报告并说明原因

## 默认假设

- 数据规模 → 首版 100 万行，作为参数可调，不直接上 500 万
- 造数确定性 → 固定随机种子，同种子必须产出同一快照
- 噪声标定轮数 → 20 轮；每个 Case 测量轮数 → 5 轮，均可配置
- 显著性门槛 → 中位数变化超过 2 × 噪声比才算收益
- 交替顺序 → baseline 与 candidate 逐轮交替，抵消漂移
- 预热 → 每侧测量前先跑若干次丢弃结果，轮数固定
- 快照摘要 → 按稳定排序逐行哈希后汇总，不依赖存储引擎物理布局
- 报告形态 → 同时输出机器可读文件与终端摘要
- 串行执行 → 任一时刻只有一个实例在被测量
- 容器数据 → 每次重建即丢弃，不做持久卷保留

## 实现范围

- 用户已固定的技术约束：Go 在 Windows 本机运行；MySQL 8.4 仅以两个独立容器提供；容器编排用 Compose；摘要算法 SHA-256
- 涉及范围：容器编排定义、基准表结构与参数化造数、快照校验、测量与统计判定、命令行入口、README 使用步骤
- 依赖前提：本机已装 Go 1.26.3、Docker 29.6.1、Compose v5.3.0（已确认）
- 当前仓库尚无 `go.mod`，故 `go vet ./...` / `go test ./...` 在首个任务建立模块后才可执行；这两条即本切片的收尾验证命令
